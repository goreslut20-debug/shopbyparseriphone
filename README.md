# Монитор цены телевизора на Shop.by → Telegram

[![Tests](https://github.com/goreslut20-debug/shopbyparseriphone/actions/workflows/tests.yml/badge.svg)](https://github.com/goreslut20-debug/shopbyparseriphone/actions/workflows/tests.yml)
[![Price monitor](https://github.com/goreslut20-debug/shopbyparseriphone/actions/workflows/monitor.yml/badge.svg)](https://github.com/goreslut20-debug/shopbyparseriphone/actions/workflows/monitor.yml)

Проверяет **Xiaomi TV S Pro Mini LED 75″ 2026 L75MB-SRU, международная версия**
и отправляет сообщения через **вашего существующего Telegram-бота**.

**Страница товара:**
https://shop.by/televizory_zhk/xiaomi_tv_s_pro_mini_led_75_2026_l75mb_sru_mezhdunarodnaya_versiya/

Сервер, постоянно работающий компьютер и установка Python для обычного использования
не нужны: проверка выполняется в GitHub Actions каждый час. Python 3.12+;
сторонних Python-зависимостей нет.

проверок GitHub Actions. С 2026-11-03 автоматически снова используется 3000 BYN.
Ежечасное расписание `17 * * * *` сохранено.

Дополнительно добавлен запуск **2026-11-02 в 14:33 по Минску (11:33 UTC)**:
`33 11 2 11 *`. Это обычная проверка: загрузка реальной страницы, штатное условие
уведомления (цена строго ниже 4000 и первое наблюдение либо снижение), отправка
обычного сообщения и сохранение состояния после подтверждения Telegram.
Это не диагностическая отправка: неизменная уже наблюдавшаяся цена не вызывает
повторного сообщения. Первоначальное состояние до запуска ещё не содержало цены.
В остальные даты этот дополнительный cron пропускает проверку: ежегодной отправки
не будет. GitHub Actions может начать выполнение позже назначенной минуты.
Для доставки должны быть заранее настроены оба Telegram Secrets.

## Когда придёт сообщение

Порог по умолчанию — **строго меньше 3000 BYN**.

- При первой проверке цена ниже порога → сообщение.
- При последующем снижении ниже порога → сообщение.
- Цена та же или выросла → тишина.
- Цена стала 3000 или выше → тишина, но новая цена сохраняется.
- После этого цена снова опустилась ниже 3000 → новое сообщение.

| Цена по порядку проверок | Результат |
|---|---|
| 2990 | Сообщение |
| 2990 | Тишина |
| 2950 | Сообщение |
| 2970 | Тишина |
| 2940 | Сообщение |
| 3000 | Тишина |
| 2995 | Сообщение |

Снижение сравнивается с **предыдущей успешной проверкой**, не с историческим минимумом
и не с последней отправленной ценой. Поэтому `2950 → 2970 → 2960` даёт сообщение
при 2950 и при 2960. Ошибочная проверка не считается успешным наблюдением.

Сообщение содержит название, текущую минимальную цену в BYN и ссылку на товар.

## 1. Настройте существующего Telegram-бота

Новый бот не нужен. Используйте токен бота, который у вас уже есть.

1. Откройте в Telegram чат с этим ботом и нажмите **Start / Запустить**
   или отправьте `/start`. Бот не может первым написать пользователю,
   который не начал с ним диалог.
2. Подготовьте **chat ID** получателя. Для личного чата это ваш Telegram user ID:
   его можно узнать у `@userinfobot` или взять из уже работающей конфигурации.
   Для группы нужен ID именно группы, часто отрицательный; добавьте туда
   существующего бота и разрешите отправку сообщений. Для канала боту нужны
   права на публикацию; chat ID может быть `@имя_публичного_канала`.
3. Откройте [настройки Secrets этого репозитория](https://github.com/goreslut20-debug/shopbyparseriphone/settings/secrets/actions):
   **Settings → Secrets and variables → Actions → Secrets**.
4. Нажмите **New repository secret** и добавьте две записи:

   | Name | Secret |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | Токен вашего существующего бота |
   | `TELEGRAM_CHAT_ID` | ID чата-получателя |

Если записи уже существуют, при необходимости обновите их. Значения GitHub
после сохранения не показывает — это нормально. **Не вставляйте токен в код,
README, issue, сообщение в чате или логи.**

Монитор использует только `sendMessage`: не запускает polling, не читает
`getUpdates` и не меняет webhook существующего бота.

## 2. Разрешите GitHub Actions сохранять состояние

1. Откройте **Settings → Actions → General**.
2. Убедитесь, что Actions разрешены и разрешено использование официальных
   `actions/checkout`, `actions/setup-python`, `actions/upload-artifact`.
3. В **Workflow permissions** выберите **Read and write permissions**,
   затем **Save**.

В самом `monitor.yml` также явно задано `permissions: contents: write`.
Используется встроенный `GITHUB_TOKEN`, отдельный GitHub-токен добавлять не нужно.
Workflow тестов имеет только право чтения. Если политика организации ограничивает
права, потребуется помощь её администратора.

Для прямого обновления JSON ветка `main` должна разрешать запись от GitHub Actions.
Если вы добавили защиту ветки с обязательным pull request, настройте допустимое
исключение для этой автоматизации. Право одобрять pull requests для бота не нужно.

## 3. Проверьте реальную цену вручную

1. Откройте вкладку **Actions**.
2. Слева выберите **Shop.by price monitor**.
3. Нажмите **Run workflow**, оставьте ветку `main`.
4. Отметьте **Только проверить реальную цену** (`dry_run`).
5. Вторую галочку не ставьте. Нажмите зелёную кнопку **Run workflow**.
6. Откройте появившийся запуск, затем job **monitor** и шаг
   **Check price or run an explicitly selected diagnostic**.

Ожидаемый вид строки:

```text
Нужный товар подтверждён. Минимальная цена: 3400.00 BYN; порог: 3000.00 BYN.
```

Это пример, а не зафиксированная цена. Пробный режим читает настоящую страницу,
не вызывает Telegram и не изменяет JSON; работает даже до настройки Secrets.

## 4. Проверьте отправку в Telegram

Ещё раз нажмите **Run workflow**, но теперь:

- `dry_run` выключен;
- **Только отправить тест связи в Telegram** (`test_telegram`) включён.

Придёт явно помеченное **тестовое сообщение**, независимо от рыночной цены.
Этот режим не проверяет Shop.by и не изменяет состояние мониторинга.
В логах должна появиться строка `Telegram подтвердил отправку тестового сообщения`.
Проверьте и сам чат. Одновременно выбирать оба диагностических режима нельзя.

После этого запустите workflow **с обеими галочками выключенными** — это обычная
проверка с сохранением состояния. Если цена 3000 BYN или выше, отсутствие сообщения
является правильным результатом. На первой успешной проверке появится коммит
`Update Shop.by price state` от `github-actions[bot]`.

Если Secrets отсутствуют, обычный запуск завершится с понятной ошибкой даже при
высокой цене. Это помогает обнаружить ненастроенный Telegram заранее.

## Расписание и порог

Файл [.github/workflows/monitor.yml](.github/workflows/monitor.yml):

```yaml
schedule:
  - cron: '17 * * * *'
```

Это **каждый час на 17-й минуте, UTC**. Минута выбрана не нулевая, чтобы меньше
попадать в пик нагрузки GitHub. Например, `37 * * * *` — каждый час на 37-й минуте.
Измените файл через GitHub и сохраните коммит в `main`.

Порог меняется в этом же файле:

```yaml
PRICE_THRESHOLD_BYN: '3000.00'
```

Указывайте положительную сумму, десятичный разделитель — точка. Сравнение строгое:
при пороге 3000 цена ровно 3000 не подходит. Изменение порога само по себе
не обнуляет историю и не вызывает сообщение при неизменной цене.

GitHub Actions запускает задания по расписанию с возможными задержками и при
высокой нагрузке может пропустить запуск. Workflow должен находиться в основной
ветке. В публичном репозитории расписание может автоматически отключиться после
60 дней без активности; включите его снова через **Actions → нужный workflow →
Enable workflow**. При неизменной цене этот проект не делает пустые коммиты.
Подробнее: [официальная документация расписания GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

## Как выбирается цена

На 2026-11-02 извлечение проверено на реальном HTTP-ответе Shop.by.
Целевая цена была **3400.00 BYN**, а рядом были другие диагонали:
65″ от 2760.00 и 55″ от 1940.00.

Парсер:

1. Проверяет `h1`, `data-model-id="1014472"` и canonical URL.
2. Ищет единственный `.ModelInfo__BlockPrice` нужной страницы.
3. Читает видимую цену **рядом со словом «от»** из `.PriceBlock__PriceValue`
   только внутри этого блока.
4. Сверяет её с `data-low-price` и `AggregateOffer.lowPrice` в JSON-LD
   того же товара; проверяет `priceCurrency="BYN"` и название модели.

Цены похожих товаров, других диагоналей, отдельных продавцов, скидки, рассрочки
и рекламные блоки не используются. JSON-LD — только дополнительная проверка,
а не запасной источник при отсутствии видимой цены. При отсутствии цены,
неоднозначности, другой модели, валюте или изменении структуры — ошибка,
без уведомления и изменения состояния. Для денег применяется `Decimal`.

Shop.by может блокировать автоматические запросы: запрос без User-Agent при
первичной проверке вернул 403; с браузерным User-Agent получен 200.
Доступ с серверов GitHub также подтверждён пробным запуском выше;
повторно проверить его можно через `dry_run`.

## Состояние и обработка сбоев

Состояние хранится в [state/price_state.json](state/price_state.json) в основной
ветке, не в краткоживущем cache/artifact. Цены записаны строками с двумя знаками.
Поля `null` означают, что проверок/уведомлений ещё не было.

- Сохраняются предыдущая наблюдавшаяся цена, дата её изменения, последняя
  отправленная цена, дата отправки и Telegram `message_id`.
- Даты и JSON не переписываются каждый час, если цена осталась прежней.
- Рост цены тоже сохраняется: иначе нельзя надёжно заметить повторный вход под порог.
- При необходимости уведомления JSON обновляется **после** ответа Telegram
  с `ok=true` и корректным `message_id`.
- При ошибке Telegram прежнее состояние остаётся: следующая проверка сможет
  повторить попытку. Секреты, chat ID, полные сетевые ошибки и ответы Telegram
  не записываются в логи/JSON.
- Запись JSON локально атомарная. После неё workflow делает коммит только JSON
  и отправляет его в GitHub, с ограниченными повторными попытками `push`.
  При конфликте с чужими изменениями останавливается, отменяет незавершённый
  rebase и сохраняет локальный JSON для восстановления, не перезаписывая удалённый.
- Запуски сериализованы через `concurrency`, каждый читает свежую основную ветку.
- При повреждённом или отсутствующем JSON автоматического сброса нет: восстановите
  последнюю корректную версию через историю файла на GitHub.

**Если отправка прошла, а сохранение в GitHub не удалось:** запуск будет красным;
на странице запуска появится artifact `price-state-recovery-<номер>` с локальным
JSON. Если лог подтверждает отправку и локальное сохранение, скачайте artifact
и восстановите этот JSON в `state/price_state.json` через GitHub **до следующего
запуска**. При необходимости временно выключите workflow через его меню **… →
Disable workflow** и включите после восстановления. Не повторяйте отправку
вручную только из-за ошибки `push`.

Telegram и GitHub не поддерживают общую транзакцию: при обрыве сразу после доставки
или до сохранения состояния возможен дубль. Абсолютную гарантию «ровно один раз»
дать нельзя. При таймауте отправка автоматически не повторяется в рамках того же
запуска: проверьте чат и состояние перед ручным перезапуском.

## Где смотреть ошибки

**Actions → Shop.by price monitor → запуск → monitor**.

| Ошибка | Что проверить |
|---|---|
| Добавьте Secrets | Две записи в Settings → Secrets and variables → Actions |
| Telegram HTTP 401 | Актуальность токена существующего бота |
| Telegram HTTP 400/403 | chat ID, `/start`, блокировку бота, права в группе/канале |
| Shop.by HTTP 403 | Доступность сайта с GitHub; запустить `dry_run` позже |
| Структура страницы изменилась / цены расходятся | HTML и селекторы; не подставлять цену другой диагонали |
| `git push` отклонён | Workflow permissions, защиту ветки, recovery artifact |
| Некорректный JSON состояния | Историю `state/price_state.json` и последнюю корректную версию |

Офлайн-тесты проходят перед каждой проверкой. Отдельный workflow **Tests** запускает
их на Python 3.12 и 3.14 при изменении кода и в pull requests. Зелёные тесты
подтверждают поведение на фикстурах; реальный доступ к сайту проверяет монитор.

## Локальный запуск для разработчика

Из корня клонированного репозитория:

```bash
python -m unittest discover -s tests -v
python -m shopby_monitor.main --dry-run
```

Установка пакетов не требуется. Для настоящей отправки нужны переменные окружения
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, настроенные локально безопасным способом;
не вписывайте их значения в команды, сохраняемые в истории терминала.
Интеграционные тесты сохранения используют `git` и `bash`; в GitHub Actions
на `ubuntu-latest` они уже установлены.

```bash
python -m shopby_monitor.main --test-telegram
python -m shopby_monitor.main
```

Локальный обычный запуск меняет JSON, но не делает `git push`: сохранение в GitHub
реализовано workflow. Локальный порог можно задать через `PRICE_THRESHOLD_BYN`.
Не запускайте локальные реальные отправки одновременно с GitHub Actions.
